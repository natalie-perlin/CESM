# Configure CESM 2.2.2 Interactive Ensemble on Derecho

This README summarizes the steps used to configure, build, and submit a CESM 2.2.2 Interactive Ensemble (IE) run on the NCAR Derecho system (`derecho.hpc.ucar.edu`).

**Created:** June 3, 2026

> **Note**
> The Interactive Ensemble couples multiple instances of ATM, LND, and ICE to a single OCN instance. All ATM/LND/ICE fluxes are averaged before being sent to the ocean (`x2o_average=TRUE`), and ocean output is broadcast back to each instance. All instances start from the same B1850 climatological initial conditions; ensemble spread is generated by small random temperature perturbations applied at initialization, with each instance using a unique random seed derived from its instance index (`inst_index` in `dyn_comp.F90`). This README is configured for **3 ensemble instances** (`NINST=3`).

## Assumptions

- You are working on NCAR Derecho.
- You have access to a valid NCAR project/account, currently
set as `UMIA0045`.
- The IE-ready CESM 2.2.2 source is on the `feature/cesm2.2.2_IE_derecho` branch of ``.https://github.com/natalie-perlin/CESM.git
- The repository includes a `SourceMods/` directory with all IE driver and CAM patches.
- You will edit placeholder paths such as `<YOUR/CASE/DIR>`, `<CESM_EXPT_DIR>`, and `<CASE_DIR>`.

## 1. Check out CESM 2.2.2 IE

Clone the IE branch:

```bash
git clone -b feature/cesm2.2.2_IE_derecho \
  https://github.com/natalie-perlin/CESM.git cesm2.2.2_IE

cd cesm2.2.2_IE

export CESM_ROOT=$PWD
export CIMEROOT=$CESM_ROOT/cime
```

## 2. Check out CESM externals

```bash
./manage_externals/checkout_externals
```

This checks out all component models (CAM, CLM, CICE, POP, etc.) at the versions specified in `Externals.cfg`. The CIME version in this branch is already set to `cime5.8.37` for Derecho compatibility.

## 3. Add Derecho CIME machine configuration

The Derecho machine configuration is included in the repository under `cime_config/machines/`. No additional copy step is needed; pass `--extra-machines-dir` at case creation to point to it.

Verify the configuration exists:

```bash
ls $CESM_ROOT/cime_config/machines/config_machines.xml
ls $CESM_ROOT/cime_config/machines/config_batch.xml
```

Edit `config_machines.xml` if needed to adjust:

- `PROJECT`
- `CIME_OUTPUT_ROOT`
- `DOUT_S_ROOT`

## 4. Create a new CESM IE case

From `$CESM_ROOT`, create a new case. The B1850 compset with f09_g17 resolution uses FV atmosphere dynamics, which matches the SourceMod provided.

Set <YOUR/CASE/DIR> to a specific case directory under the CIME_OUTPUT_ROOT defined in:

$CESM_ROOT/cime_config/machines/config_machines.xml

For example, if config_machines.xml contains:

<CIME_OUTPUT_ROOT>/glade/work/$USER/CESM2/EXPT</CIME_OUTPUT_ROOT>

then <YOUR/CASE/DIR> could be set to:

/glade/work/$USER/CESM2/EXPT/Atm10_Ocn1

The project/account can be defined either in config_machines.xml:

<PROJECT>UMIA0045</PROJECT>

or specified directly in the *create_newcase* command with:

```bash
--project UMIA0045
```

If the project is already defined in *config_machines.xml*, the *--project* option can be omitted.

Create the case:

```bash
cd $CESM_ROOT

$CIMEROOT/scripts/create_newcase \
  --case <YOUR/CASE/DIR> \
  --res f09_g17 \
  --compset B1850 \
  --project UMIA0045 \
  --machine derecho \
  --extra-machines-dir $CESM_ROOT/cime_config/machines \
  2>&1 | tee log.create.newcase.001

cd <YOUR/CASE/DIR>
export CASEROOT=$PWD
```

Save the create command for reproducibility:

```bash
cat > $CIMEROOT/scripts/newcase_IE.sh <<'EOF_SCRIPT'
#!/bin/bash
$CIMEROOT/scripts/create_newcase \
  --case <YOUR/CASE/DIR> \
  --res f09_g17 \
  --compset B1850 \
  --project UMIA0045 \
  --machine derecho \
  --extra-machines-dir $CESM_ROOT/cime_config/machines
EOF_SCRIPT
chmod +x $CIMEROOT/scripts/newcase_IE.sh
```

## 5. Configure multi-instance (IE) settings

Set the number of instances to 3 for every prognostic component except OCN. The driver requires that all active (non-stub) components share the same instance count — the only explicit exception is OCN, which may remain at 1 to enable flux averaging. In B1850, the prognostic components are ATM, LND, ICE, ROF (MOSART), GLC (CISM2), and WAV (WW3). IAC (stub SIAC) and ESP (stub SESP) are not prognostic and stay at 1.

```bash
cd $CASEROOT

./xmlchange NINST_ATM=3
./xmlchange NINST_LND=3
./xmlchange NINST_ICE=3
./xmlchange NINST_ROF=3
./xmlchange NINST_GLC=3
./xmlchange NINST_WAV=3
# NINST_OCN stays at 1 (default) — activates x2o_average=TRUE in the driver
# NINST_IAC and NINST_ESP stay at 1 — stub components, not prognostic
```

Verify the instance counts are set correctly:

```bash
./xmlquery NINST
# Expected: ATM:3, LND:3, ICE:3, OCN:1, ROF:3, GLC:3, WAV:3, IAC:1, ESP:1
```

Scale task counts so each instance has adequate resources. Query the current per-component task counts first and their corresponding ROOTPE(s):

```bash
./xmlquery NTASKS
```
NTASKS: ['CPL:1024', 'ATM:1024', 'LND:512', 'ICE:512', 'OCN:128', 'ROF:512', 'GLC:1024', 'WAV:256', 'IAC:1', 'ESP:1']

```bash
./xmlquery ROOTPE
```
ROOTPE: ['CPL:0', 'ATM:0', 'LND:0', 'ICE:512', 'OCN:1024', 'ROF:0', 'GLC:0', 'WAV:0', 'IAC:0', 'ESP:0']


NOTE:

Additional performance testing is still needed to determine appropriate PE-layout settings for Derecho, including:

NTASKS_ATM, NTASKS_LND, and NTASKS_ICE
NTASKS_CPL (which will likely be the same as NTASKS_ATM),
component root PEs, including ROOTPE_ATM, ROOTPE_LND, ROOTPE_ICE, ROOTPE_OCN, ROOTPE_WAV, and ROOTPE_CPL

These settings should be tuned so that the requested node count, wallclock time, model integration length per job, and queue wait time for resubmitted jobs are practical and efficient. For example, testing is needed to determine whether a six-month model integration per submitted job is reasonable on Derecho.

For an initial scaling test, the task count for each multi-instance component can be increased in proportion to the number of instances. With 3 instances for each prognostic component (ATM, LND, ICE, ROF, GLC), the default task count is scaled by 3 (WAV does not scale):

```bash
./xmlchange NTASKS_ATM=3072
./xmlchange NTASKS_LND=3072
./xmlchange NTASKS_ICE=3072
./xmlchange NTASKS_CPL=3072
./xmlchange NTASKS_ROF=1536    # 512 default × 3 instances
./xmlchange NTASKS_GLC=3072    # 1024 default × 3 instances
./xmlchange NTASKS_WAV=36      # wave model: not scaled, keep fixed
```

NTASKS_CPL matches NTASKS_ATM (it drives the coupler across all instances). NTASKS_WAV is kept at 36 regardless of instance count — the wave model task count does not scale with the ensemble. NTASKS_OCN remains at its default (128).

```bash
./xmlquery NTASKS_OCN
```

Run OCN component on a separate node:
```bash
./xmlchange ROOTPE_OCN=3072
```

The totalPE would then be 3072+128=3200, which scales to 25 nodes on Derecho with (Tasks Per Node) TPN=128.

## 6. Copy IE SourceMods into the case

The repository's `SourceMods/` directory contains IE-modified driver files and the per-dynamics CAM patch. Copy the driver SourceMods and the FV atmosphere patch (for B1850/f09_g17):

```bash
# Driver modifications (Phase 1 IE fixes: ocn(1) -> ocn(eoi))
cp $CESM_ROOT/SourceMods/src.drv/cime_comp_mod.F90  $CASEROOT/SourceMods/src.drv/
cp $CESM_ROOT/SourceMods/src.drv/prep_ocn_mod.F90   $CASEROOT/SourceMods/src.drv/

# CAM FV dynamics: per-instance random temperature perturbation
cp $CESM_ROOT/SourceMods/src.cam.fv/dyn_comp.F90    $CASEROOT/SourceMods/src.cam/

# Suppress MARBL ocean biogeochemistry diagnostics
echo ' ' > $CASEROOT/SourceMods/src.pop/ecosys_diagnostics
```

> **Dynamics note**: `src.cam.fv/dyn_comp.F90` is for the FV dynamical core used by B1850. If using a different compset with SE dynamics, use `src.cam.se/dyn_comp.F90` instead.

Verify the SourceMods are in place:

```bash
ls $CASEROOT/SourceMods/src.drv/
ls $CASEROOT/SourceMods/src.cam/
```

## 7. Prepare the case setup

### 7.1 Check and adjust run/archive paths

```bash
./xmlquery CASEROOT,RUNDIR,DOUT_S_ROOT
```

Move the run directory to scratch for better I/O performance:

```bash
mkdir -p ${SCRATCH}/<CESM_EXPT_DIR>/<CASE_DIR>/run

./xmlchange RUNDIR=${SCRATCH}/<CESM_EXPT_DIR>/<CASE_DIR>/run
./xmlquery RUNDIR
```

### 7.2 Run `case.setup`

```bash
./case.setup 2>&1 | tee log.case.setup.001
```

`case.setup` generates the per-instance namelist files:

```text
user_nl_cam_0001 ... user_nl_cam_0003
user_nl_clm_0001 ... user_nl_clm_0003
user_nl_cice_0001 ... user_nl_cice_0003
user_nl_pop (single OCN instance)
```

All instances share the same B1850 climatological initial conditions. Ensemble spread is generated by per-instance temperature perturbations in the atmosphere (see section 7.3).

### 7.3 Activate temperature perturbations

All instances start from the **same B1850 climatological initial conditions file** (`ncdata`). Ensemble spread is generated entirely by `pertlim`, a small random perturbation applied to the initial temperature field in `dyn_comp.F90`.

The IE SourceMod modifies the random seed to include the instance index:

```fortran
rndm_seed = i + (j-1)*nglon + (inst_index-1)*nglon*nglat
```

This guarantees that each ensemble member receives a distinct perturbation pattern even though all start from the same IC file. Add the same `pertlim` magnitude to every CAM instance namelist:

```bash
for inst in $(seq -w 1 3); do
  echo "pertlim = 1.e-14" >> $CASEROOT/user_nl_cam_${inst}
done
```

A value of `1.e-14` introduces perturbations of order 10⁻¹⁴ K, small enough to be physically negligible at initialization but sufficient to break symmetry and allow each instance to evolve independently.

### 7.4 Update the POP namelist

```bash
echo 'n_tavg_streams = 3' >> $CASEROOT/user_nl_pop
```

## 8. Build the case

### 8.1 Clean any previous build

```bash
./case.build --clean
```

### 8.2 Set Derecho modules and NetCDF paths

```bash
module reset
module list
```

The working module environment is:

```text
1) ncarenv/24.12
2) craype/2.7.31
3) intel/2024.2.1
4) ncarcompilers/1.0.0
5) libfabric/1.15.2.0
6) cray-mpich/8.1.29
7) hdf5/1.12.3
8) netcdf/4.9.2
```

Set NetCDF paths:

```bash
export NETCDF_C_PATH="$(nc-config --prefix)"
export NETCDF_FORTRAN_PATH="$(nf-config --prefix)"

```

### 8.3 Build

```bash

```

Confirm that the preprocessor defines and SourceMods were applied correctly:


## 9. Configure runtime parameters and submit

### 9.1 Set run length and resubmission

For a functionality test, run two 6-month segments (initial segment plus one resubmission):

```bash
./xmlchange STOP_OPTION=nmonths,STOP_N=6
./xmlchange RESUBMIT=1
./xmlchange DOUT_S=TRUE
./xmlchange --subgroup case.run      JOB_WALLCLOCK_TIME=04:00:00
./xmlchange --subgroup case.st_archive JOB_WALLCLOCK_TIME=00:30:00
```

> The wallclock time is longer than the single-instance case because 3 instances of ATM, LND, ICE, ROF, GLC, and WAV are being advanced simultaneously.

### 9.2 Submit

```bash
./case.submit >& log.case.submit.001 &
```

## 10. Verify IE functionality

### 10.1 Check that flux averaging is active

After the run starts, search the coupler log for the averaging confirmation message:

```bash
grep "x2o averaging on over instances" $RUNDIR/cpl.log.*
```

Expected output:

```
x2o averaging on over instances =           3
```

### 10.2 Check that per-instance perturbations are applied

Search the atmosphere log for each instance:

```bash
grep "Adding random perturbation" $RUNDIR/atm.log.*_0001.*
grep "Adding random perturbation" $RUNDIR/atm.log.*_0002.*
```

Expected output (instance index varies):

```
Adding random perturbation bounded by +/- 1.E-14 to initial temperature field (ensemble instance 1)
Adding random perturbation bounded by +/- 1.E-14 to initial temperature field (ensemble instance 2)
Adding random perturbation bounded by +/- 1.E-14 to initial temperature field (ensemble instance 3)
```

### 10.3 Check output files

A successful IE run produces:

- 3 sets of ATM history files: `*.cam_0001.h0.*.nc` … `*.cam_0003.h0.*.nc`
- 3 sets of LND history files: `*.clm2_0001.h0.*.nc` … `*.clm2_0003.h0.*.nc`
- 3 sets of ICE history files: `*.cice_0001.h0.*.nc` … `*.cice_0003.h0.*.nc`
- 1 set of OCN history files: `*.pop.h.*.nc` (single ocean, receives averaged forcing)

## IE coupling summary

| Component pair | Direction | Mode |
|----------------|-----------|------|
| ATM/LND/ICE → OCN | Flux merging | Average of all 3 instances → OCN(1) |
| OCN → ATM/ICE | State broadcast | OCN(1) output replicated to all 3 instances |
| ATM ↔ LND | Exchange | 1-to-1: ATM(N) ↔ LND(N) |
| ATM ↔ ICE | Exchange | 1-to-1: ATM(N) ↔ ICE(N) |

The averaging and broadcasting are controlled by `x2o_average=.TRUE.` in the driver, set automatically when `NINST_OCN=1` and `NINST_ATM > 1`. See `SourceMods/src.drv/prep_ocn_mod.F90` for the merging implementation and `SourceMods/src.drv/README_IE_MODIFICATIONS.md` for a full description of driver changes.
